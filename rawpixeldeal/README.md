# RawPixelDeal Module - 医学图像预处理与调窗

本模块主要负责医学图像（如 CT, X-ray）的底层像素处理，利用 OpenCV 提供高性能的图像增强、去噪、色度反转及自适应调窗功能。

## 1. 预处理方法与顺序说明

在医学图像处理流程中，算子的执行顺序对最终质量至关重要。推荐的标准流水线顺序如下：

1.  **图片裁剪 (Tailor)**：
    -   **逻辑**：通过 OTSU 和边缘检测自动定位主体区域并旋转校正。
    -   **原因**：减少背景干扰，使后续的直方图统计和调窗更聚焦于有效病灶区域。
2.  **色度反转 (Invert LUTs)**：
    -   **逻辑**：在原始像素域执行查找表映射。
    -   **场景**：用于模拟 Monochrome1/2 切换，辅助观察特定密度组织。
3.  **HU 值校正 (HU Convert)**：
    -   **逻辑**：将裸像素转换为亨氏单位（HU）。
    -   **原因**：这是物理意义的归一化，是后续临床调窗算法的基础。
4.  **图像去噪 (Denoising)**：
    -   **方法**：双边滤波（CT 首选）、高斯、中值等。
5.  **调窗映射 (Windowing)**：
    -   **逻辑**：应用各种临床算法（如 72% 累计面积法、自适应直方图法）将高动态 HU 数据映射到 8-bit 可视化区间。

## 2. 操作指南 (CTPreprocessFragment)

界面按功能逻辑划分为以下四个核心区域：

### A. 预处理操作 (Preprocess Operations)
-   **功能**：手动勾选算子（裁剪、去噪、校正等）。
-   **执行**：点击 `LOAD & DISPLAY`。
-   **显示**：结果显示在右侧（After），左侧（Before）清空。

### B. 一键流水线 (One-Click Pipelines)
-   **Standard Full**：执行官方标准全流程。
-   **Tailor + Standard**：执行自动裁剪加上标准处理流程，适合去除无效背景。

### C. 色度反转 (Chromatic Inversion)
-   **功能**：专门针对图像极性进行反转处理。
-   **执行**：点击 `Apply Invert LUTs`。

### D. 调窗增强与对比 (Windowing & Comparison)
-   **功能**：选择特定的临床调窗算法（如 Adaptive）。
-   **执行**：点击 `RUN WINDOWING`。
-   **对比显示**：
    -   **左图 (Before)**：仅执行预处理，采用默认线性映射。
    -   **右图 (After)**：执行预处理后，应用所选调窗算法的效果。
    -   **目的**：直观评估调窗算法对细节表现力的提升。

## 3. 核心功能与算法优化总结

本模块近期针对 `FT46` 等探测器原始数据（Raw）进行了深度算法优化，解决了背景干扰、动态范围压缩及黑屏等问题。

### 3.1 统计数据导出功能
-   **功能**：一键导出 `pixel_array.txt`（原始像素值）、`histogram.txt`（灰度直方图）和 `smoothed_data.txt`（平滑后数据）。
-   **存储路径**：同时写入内部存储 (`/data/data/.../files`) 和外部私有存储 (`/sdcard/Android/data/.../files`)，方便调试。
-   **意义**：通过文本化分析原始探测器输出，辅助算法参数（如 $I_0$、$\sigma$）的精准标定。

### 3.2 物理级 Log 变换算子
-   **公式**：$Y = 1000 \cdot \ln(I_0 / (I + 1))$。
-   **优化要点**：
    -   **背景抑制**：引入 99.5% 分位数计算 $I_0$，排除探测器热点像素干扰。
    -   **动态范围扩展**：输出放大 1000 倍，确保在 HU 校正后的浮点域仍保有充足的灰度层次（数千个阶梯而非几十个）。
-   **排序规则**：强制 `Log变换` $\rightarrow$ `HU校正`。防止 HU 域负值进入对数运算导致 NaN（黑屏）。

### 3.3 智能波峰面积调窗算法 (Peak Area Auto)
-   **算法原型**：基于 `image_processing_jni.c` 移植并升级。
-   **核心改进**：
    -   **主体 ROI 检测**：统计前自动探测人体区域，排除空气背景峰的误导。
    -   **“组织锁定”逻辑**：若最大峰位于低 HU 区（背景），则自动切换至次大峰（组织）。
    -   **安全窗宽保护**：设定最小 400 HU 窗宽，防止高对比度导致的视觉生硬。

### 3.4 调窗虚化问题专项优化 (2026.07.28)
-   **问题背景**：针对 `FT46` 数据在预处理后（含 HU 校正与双边去噪）应用 `Peak Area` 算法出现图像过度平滑、对比度不足（虚化）的问题。
-   **优化措施**：
    -   **精细化平滑**：将直方图高斯平滑系数 `sigma` 从 20.0 降至 8.0，显著提升对细小组织波峰的识别精度，防止波峰融合。
    -   **对比度收紧**：将边缘检测阈值 `thE` 从 0.55 提升至 0.75，使计算出的窗宽（Window Width）更加聚焦于核心组织区域。
    -   **双端背景抑制**：优化波峰搜索逻辑，同时检测直方图两端（0-15% 和 85-100%）的背景干扰，完美兼容 `Invert LUTs` 开启后的反转数据。
    -   **临床窗宽约束**：引入 `[300, 1500]` HU 的动态窗宽保护区间，从算法层面强制规避因参数偏移导致的超大窗宽虚化。
-   **预期效果**：在保持去噪效果的同时，显著增强图像的层次感和边缘锐利度，达到标准 DICOM 查看器的视觉水平。

### 3.5 骨骼细节增强专项优化 (2026.07.29)

**问题诊断**：
通过对比 `CR2024051209455920240512095131FT46.dcm`（标准图，WL:1939，清晰锐利）与项目生成的 `20260728_1855.dcm`（WL:1708, WW:2309，边缘模糊，纹理细节丢失），发现主要问题：

1.  **虚化效果**：图像整体对比度不足，边缘模糊
2.  **锐化不足**：骨皮质、骨小梁等微细纹理细节丢失
3.  **局部对比度偏低**：软组织层次感不足

**根本原因分析**：

| 问题点 | 原参数 | 影响 |
|--------|--------|------|
| Peak Area 高斯平滑过度 | sigma=8.0 | 过度平滑掉骨小梁等微细纹理 |
| Peak Area 边缘检测阈值偏低 | thE=0.75 | 窗宽过大(WW:2309)，导致对比度不足 |
| 双边滤波保边能力不足 | sigmaColor/SigmaSpace=50 | 边缘保持不充分，平滑了重要纹理 |
| USM 锐化强度保守 | strength=0.6 | 对骨骼细节增强不足 |
| CLAHE 局部增强有限 | clip=2.0 | 局部对比度提升不够 |

**核心改进方案**：

#### 3.5.1 Peak Area 算法优化 (CtSeriesProcessor.cpp)
-   **降低高斯平滑强度**：sigma: 8.0 → 3.0
    -   **原因**：减少对骨小梁、骨纹理等微细结构的平滑，保留更多高频信息
-   **优化边缘检测阈值**：thE: 0.75 → 0.70
    -   **原因**：适度收紧窗宽范围，提高图像对比度，减少虚化
-   **扩展背景抑制范围**：
    -   左端背景：0-15% → 0-20%
    -   右端背景：85-100% → 80-100%
    -   **原因**：更有效地抑制空气背景和极端高值干扰
-   **降低临床窗宽保护下限**：400 HU → 350 HU
    -   **原因**：允许更窄的窗宽，进一步提高对比度

#### 3.5.2 预处理参数优化 (CTPreprocessFragment.kt & MedicalCTPreprocess.cpp)
-   **双边滤波增强保边**：sigmaColor/SigmaSpace: 50 → 75
    -   **原因**：增强边缘保持能力，在去噪的同时更好地保留骨骼边缘和骨小梁纹理
-   **USM 锐化强度提升**：strength: 0.6 → 0.8
    -   **原因**：增强骨皮质和骨小梁的边缘锐度，突出骨骼纹理细节
-   **CLAHE 局部对比度增强**：clip: 2.0 → 3.0
    -   **原因**：增强局部对比度，改善软组织层次感，减少整体虚化效果

**改进效果预期**：

| 优化维度 | 预期改善 |
|----------|----------|
| **边缘锐度** | 骨皮质边缘更清晰，骨折线更易识别 |
| **纹理细节** | 骨小梁网状结构更清晰，骨纹理更丰富 |
| **整体对比度** | 软组织层次感增强，病灶边界更明确 |
| **虚化消除** | 整体图像更接近标准DICOM查看器效果 |

**技术要点总结**：

1.  **算法层面**：通过降低平滑强度和提高对比度控制参数，减少过度平滑
2.  **参数调优**：平衡去噪与细节保留，避免过度平滑导致的虚化
3.  **临床适配**：针对骨骼CT特点，优化锐化和局部增强参数
4.  **质量对标**：以标准DICOM查看器效果为基准，反向优化算法参数

**注意事项**：
-   本次优化针对骨骼CT图像，对于其他部位（如肺部、软组织）可能需要调整参数
-   锐化增强主要用于可视化观察，定量分析应使用未锐化的原始数据
-   参数调整需结合具体临床需求，避免过度增强导致伪影

## 4. 预处理方法总结

| 预处理方法 | 核心原理 | 预期达到的效果 |
| :--- | :--- | :--- |
| **图片裁剪** | 轮廓提取 + 旋转校正 | 去除无效背景，使调窗算法统计更加精准。 |
| **Log 变换** | 对数域非线性压缩 | **Raw 数据必备：** 将强度空间转为衰减空间，拉开层次。 |
| **Invert LUTs**| 16-bit 查找表反转 | 改变图像黑白极性，支持 HU 域动态反转。 |
| **HU 校正** | 物理映射 (SV -> HU) | 实现图像标准化，使数据具有临床对比性。 |
| **双边去噪** | 保边滤波 | **CT首选：** 在滤除噪声的同时保留组织边缘。 |
| **CLAHE 增强** | 局部自适应均衡 | 提升软组织细节可见度，抑制噪声。 |

## 5. 技术栈说明

-   **核心层**：C++ 17 + OpenCV 4.x，确保毫秒级处理响应。
-   **接入层**：JNI + Kotlin Coroutines，实现异步无损处理。
-   **显示层**：Android ImageView，支持左右分栏类比显示。
