最佳窗位窗宽计算数据源选择
算出最佳的窗位窗宽是用原始像素数据缓冲区的数据计算，还是用裁剪、预处理后的数据进行计算呢？
核心结论（CT 投影→重建→图像窗宽窗位场景，区分两个容易混淆的阶段）
先分清两件事：
1）投影域（FPGA 原始像素、预处理、平滑、校正）
2）重建后的图像域（最终断层图像，HU 值）
一、先说最常见场景：你做图像显示的窗宽窗位（HU 窗）
最佳窗位窗宽，必须基于【重建完成、换算成 HU 值的断层图像】计算，不能直接拿原始探测器像素缓冲区算。
原因：
原始 ADC 像素 ≠ CT 值（HU）。
原始像素包含：暗电流、偏置、增益、射束硬化、对数变换前的信号，物理含义是探测器接收光子强度，不是组织衰减系数。
哪怕你做了平滑、裁剪、原始投影预处理，依旧是投影数据（sinogram），不是断层图像，不存在 HU，无法直接用于人体组织窗宽窗位自适应计算。
链路：原始像素缓存 → 预处理 / 裁剪 / 平滑 → 对数变换 → 重建 → HU 图像 → 自动计算最优窗宽窗位
二、如果你是【投影域做阈值 / 像素动态范围裁剪】（不是临床 HU 窗）
如果你仅仅是为了：
剔除探测器暗噪声
找到有效信号区间，用于投影数据归一、图像预处理截断
这时可以用：经过基础预处理后的投影数据，而不是裸原始 ADC。
顺序建议：
原始 pixel_buf → 去暗场、坏道校正 →（可选平滑）→ 统计直方图 → 确定投影信号有效上下限。
⚠️ 这个得到的 “上下阈值”不能当成临床窗宽窗宽，只是投影预处理截断阈值！很多项目在这里混淆踩坑。
三、回答你的直接问题：自适应窗算法数据源选择
方案 A：临床自适应窗（显示人体组织，标准流程）
数据源：重建后的 HU 图像
流程：
原始像素缓冲区 → 完整投影预处理（裁剪、平滑、校正、对数）
FBP / 迭代重建得到断层图像
图像像素转为标准 HU 值
统计 HU 直方图 → 自动求解最佳窗宽窗位
✅ 标准、符合 DICOM 规范、可用于临床显示
方案 B：有人偷懒 —— 直接用重建前投影直方图
❌ 强烈不推荐用于最终图像显示窗宽窗位
投影域信号和 HU 不存在线性对应；投影直方图分布 ≠ 断层图像 HU 分布，算出的窗参数失真，软组织对比度异常。
四、细化：预处理做到哪一步再统计直方图算窗？
1）若是【图像域自动窗（目标：给 DICOM 图像设置 WW/WL）】
统计对象：重建 HU 图像
前置预处理（图像层面）：
重建输出 HU 数组 → 剔除空气极值、截断超出人体有效 HU 范围 → 统计直方图 → 计算最优窗
2）若是【投影域预处理阈值截断（只做 Sinogram 预处理）】
统计对象：校正后的投影像素
前置：
原始像素 → 暗帧校正、增益校正、坏像素剔除
不建议直接裸原始缓冲区统计
原始 ADC 里含有大量探测器偏置、暗电流噪声，直方图基线偏移，算出的阈值不准。
五、结合你手头三份 txt 文件对应关系
pixel_array.txt：原始像素（投影域，不可直接算临床窗宽窗位）
smoothed_data.txt：平滑后投影（依然是投影域，同样不行）
只有重建生成断层图像后，对图像像素统计直方图，算出的窗宽窗位才有临床意义
六、工程实操建议（适配你 JNI 窗宽窗位代码）
不要在 FPGA 原始像素缓存阶段去计算最终显示用 WW/WL；
重建出 HU 图像后再做直方图统计求自适应窗；
例外：若你需要动态调节投影预处理截断阈值（抑制探测器噪声），可以在校正后的投影数据上统计；
区分两个概念，代码变量名做好隔离：
proj_min/proj_max：投影预处理阈值
window_width/window_level：图像显示窗参数（基于 HU）
