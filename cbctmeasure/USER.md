# CBCT 三维测量与手术规划 — 使用说明

适用页面：**抽屉菜单 → CBCT Measure**（`nav_cbct_measure`）。
本页面在 `:cbctdeal` 已经建好的三维画面上做测量与规划，**不重新加载数据**，所以进入前请先确认已经解析过一次序列（在本页解析也可以，见下）。

页面是一列竖排面板，从上到下固定 7 个区块：`1) 数据源` · `2) 视口` · `3) 三维画面`（下面紧跟 5 个快捷按钮） · **tab 切换的 `4) 测量工具与 ROI` / `5) AI 辅助分析 (Phase 2)`** · `6) 结果 Results`（可折叠） · `7) 归档与报告`，最后一段是摘要区。
测量与 AI 各自占满一整页，切 tab 只是显隐，**不会重建会话**，正在描记的草稿与已跑出的 AI 结果都还在。

> 本页所有数值均由体数据直接计算，**只用于方案设计参考，任何诊断与手术决策必须由临床医师复核**。报告每页页脚都印有这条提示。

## 1. 准备：拿到体数据

页面顶部「1) 数据源 Series Source」四种方式，任选其一：

| 按钮 | 作用 | 什么时候用 |
|---|---|---|
| 加载 neck_ct | 读内置演示序列（512×512×265，体素 0.7031×0.7031×2.5000 mm） | 快速体验、演示、回归（**头颈部**，不适合做牙齿自动分割） |
| 选择目录 (SAF) | 系统目录选择器挑一个 DICOM 序列目录 | 自己的数据，路径不确定时 |
| 解析并进入测量 | 解析上方路径里的序列并建会话 | 手输绝对路径后 |
| **加载牙科 CBCT** | 弹出内置**牙科 CBCT** 病例列表（公开 DentVoxel 临床采集，已随包放在 `assets/dental_cbct/`（本模块内），192×192×128 @0.60 mm，每例 128 张），选一例即自动释放到应用私有目录、填好路径并开始解析 | **要用 AI 辅助分析（第 7 节）时必须用这一项**：模型是在牙科 CBCT 上训练的，neck_ct 这类头颈序列跑出来的掩膜没有意义。AI 页（tab 5）上另有同名「换一例牙科 CBCT」按钮，走的是同一条路径 |

列表里每一例都会显示它的角色说明：`dentvoxel_0101` 是**模型没见过**的测试例（精度指标以它为准），`dentvoxel_0021` 是**参与过训练**的例（分割观感最干净，但它的分数不能当泛化指标）。第一次进某例会先拷贝 128 个 DICOM 文件（日志 `病例 dentvoxel_0101 已释放 128 张`），之后复用同一目录，秒开。

解析完成后「2) 视口 Viewport」上方会显示 `解析完成 (xxxx ms)`，同时三维画面出现。
若显示 `(waiting for parse)` 或报错，说明序列目录里没有可读的 DICOM，请先回 CBCT Parse 页确认。

## 2. 画面操作（任何工具下都能用）

| 操作 | 效果 |
|---|---|
| 单指拖动 | VR 模式旋转；测量工具下由该工具接管（不会同时旋转） |
| 双指捏合 / 双指拖动 | 缩放 / 平移 |
| VR 体绘制 · MPR 切面 | 体渲染与三平面切面互切 |
| Axial / Coronal / Sagittal + 位置滑条 | MPR 下切面与层位（`132/264` 是当前层/总层） |
| 窗宽 WW · 窗位 WC | 实时调窗，看骨/软组织不同对比度 |
| 复位相机（快捷行） | 回到初始视角与初始缩放 |

测量点位的精度依赖画面对比度：**取骨面点之前先把窗宽调到骨骼合适区间**（演示数据可用 CBCT Parse 页的「骨骼窗」量级），否则表面拾取会落在错误的层。

## 3. 测量工具（tab「4) 测量工具与 ROI」）

选一个工具，`3) 三维画面` 正下方那行会给出该工具的操作引导文案（`浏览：单指旋转，双指缩放/平移`）。

引导文案下面是一行**常驻快捷按钮**（与 tab 无关，切到 AI 页也还在），从左到右：

| 按钮 | 作用 |
|---|---|
| 撤销取点 | 去掉当前草稿的最后一个点；同时会冲掉上一次「没点中」的残留提示 |
| 闭合路径 | 面积多边形的**不依赖命中起点**的收尾方式：点够 3 个点就能直接提交。点数不足时草稿保持原样，只给原因（见第 9 节） |
| 复位相机 | 回到初始视角与初始缩放 |
| 丢弃草稿 | 放弃当前这一次未完成的描记，图形与提示行一起清空 |
| 清空全部 | 二次确认后清空本页所有条目（不影响磁盘上的归档文件） |

快捷行下面是工具选择（第一行）与该工具的子类型（第二/三行，随工具变）。

| 工具 | 子类型 | 手势 | 完成条件 |
|---|---|---|---|
| 浏览 | — | 单指旋转 / 双指缩放平移 | 不产生条目 |
| 测距 | 两点距离 / 点到线 / 弧线长度 / HU 采样 / 骨密度 / 牙弓弧线 / 排列角度 / 中线偏移 / 覆合覆盖 | 见下 | 点够点数自动提交 |
| 测角 | — | 依次点 A / **B(顶点)** / C | 三点取完即提交（顶点是第 2 个点） |
| 体积 | — | **按住并拖动**画出一个盒 | 松手即建「ROI 盒」+ 体积测量；每边需 ≥1mm，否则提示「区域太小…已取消」 |
| 面积 | — | 在 MPR 切面上逐笔点出多边形（≥3 点） | **再次点击起点附近（2mm 内）闭合**，或按快捷行的**「闭合路径」**直接提交（放大后 2mm 不到一个屏幕像素，点不中起点时用它）；点到 120 点会自动闭合 |
| ROI | — | 用同一 tab 下半部分的「阈值 ROI」面板建阈值/组合 ROI | 面板操作即生效 |
| 种植体 | — | 点击牙槽嵴顶放置入口点 | 点一下就落一颗，随后在结果行里调参数 |
| 神经管 | — | 在当前层逐点描记，切层继续 | 按「神经管描记」（第 4 节）新建路径后逐层点；也可在结果行里改管道半径 |
| 标注 | 文字 / 线段 / 箭头 / 自由曲线 / 环形 / 截面 / 截图圈注 | 文字：点击落点；线段与箭头：点两端；自由曲线：按住拖动；环形：点圆心再拖到边缘；截面：在当前切面点击；截图圈注：点击打圈注（记录像素坐标） | 各自完成后进入结果列表 |

子类型说明（测距条第二行）：

* **弧线长度**：按住沿骨面拖动描记，松手提交（最多 80 个采样点，系统会做深度锁层与中值滤波，避免跳到别的骨面）。
* **HU 采样**：单击取该体素中心原始 HU（不做插值），并给出推断组织名。
* **骨密度**：单击 ROI 内的骨小梁区域，返回均值/标准差/最大/最小 HU。
* **牙弓弧线 / 排列角度 / 中线偏移 / 覆合覆盖**：正畸量。牙弓弧线要在冠状面沿牙弓拖动描记，其余按引导点击对应标志点。

拖动类工具（体积、弧线、自由曲线、环形）**必须按下的那一点就落在有效表面上**：按下点没拾取到，整条轨迹都不会有采样点，表现为「拖了半天没反应」，此时提示行会给出原因（`未拾取到点：请对准骨面或切面再点击` / `未拾取到骨面：请对准牙槽嵴点击`）。

## 4. ROI 与量化（tab「4) 测量工具与 ROI」的下半部分）

| 控件 | 用法 |
|---|---|
| HU 低 / HU 高 | 阈值区间，演示数据骨骼可取 200~3000 |
| 建 HU 阈值 ROI | 按当前 HU 区间建 R-01 阈值 ROI（全体积内筛选） |
| 隔离显示 | 只显示当前选中的 ROI，便于看轮廓 |
| 组合 ROI | 依次弹三次列表选 A / B / C 与两种运算符（`∩` `∪` `−`），生成组合 ROI。子 ROI 必须已存在，否则会提示「缺少子 ROI」而不是给一个错误体积 |
| 神经管描记 | 新建一条「神经管 N」路径（默认半径 **1.5mm**，S-05 的安全距离按它外推）并直接进入描记态：自动切到 MPR 与「神经管」工具，日志/弹窗给 `已新建神经管 id，请在切面上逐层点击描记`。没解析序列时会先提示「请先解析序列」 |

**查看量化结果**：在「6) 结果 Results」列表里**点一下 ROI 那一行**，下方摘要区会显示：

```
【ROI #12 量化】
体积 38.124 cm³ | 平均 29.6 HU | 标准差 219.6 | 范围 -997~873
权重体素 30846.0 | 遍历 31556/31556 | 耗时 12 ms
```

* **权重体素**：按角点比例累计的有效体素数（边界体素算部分权重，所以可以是非整数）；
* **遍历 a/b**：实际扫描的体素数 / 包围盒体素数，用来看裁剪是否生效；
* 大盒（百万级体素）单次量化约 20ms，会有一瞬间的等待。

截面（平面）ROI 只统计**你勾画那一层**内的多边形区域，不会把整个半空间算进来。

## 5. 种植体规划与安全判定

1. 选「种植体」工具，在牙槽嵴顶点击放置入口点（可连续放多颗）；
2. 在结果列表点对应行可改 **直径 / 长度 / 俯仰 / 偏转 / 深度**；
3. 神经管必须描记后才会有神经距离读数：按「4) 测量工具与 ROI」里的**神经管描记**按钮新建路径（默认半径 1.5mm）→ 在切面上逐层点出路径，随后可在结果行里调管道半径；
4. 颜色即安全等级（PRD 判据）：
   * **绿色** 安全（骨高 ≥10mm、骨宽 ≥6mm、神经距离 ≥2mm、间距 ≥3mm）
   * **黄色** 临界
   * **红色** 不安全（含神经距离 <2mm）
   未描记神经管时该项显示为「未测量」，不会伪造距离；
5. 任一种植体或神经管的增删改都会触发**整方案重算**，同一条列表里的其它行数值会一起更新。

## 6. 结果列表（「6) 结果 Results」，可折叠）

标题行本身就是读数：`6) 结果 Results（N 项）`，右侧 `点击折叠` / `点击展开`，箭头 `▾` / `▸`。
**折叠只隐藏列表本体，标题行始终留着**，所以收起后仍能看到共几项。
条目 ≤ 6 行时面板自动展开；超过 6 行自动收起一次，但你手动点过一次之后就以你的选择为准，后续增删不再自动收起。

每行三段信息：`#编号 类型名` / 主数值 / 概要（点名、关联 ROI、备注）。

| 操作 | 效果 |
|---|---|
| 点击行 | 高亮该条目的叠加图形；ROI 行顺带跑一次量化并写入摘要区；神经管行会自动切到描记态并定位该路径；标注行会弹出文本编辑 |
| 显示/隐藏（行右勾） | 单独控制该条目的叠加图形可见性 |
| 删除（行右按钮） | 删除该条目；种植体/神经管删除后方案会重算 |

## 7. AI 辅助分析（tab「5) AI 辅助分析 (Phase 2)」）

这一页是独立的 `CbctAiFragment`，嵌在测量页的 tab 5 里，与测量工具页共用同一个会话（切 tab 不重建会话、不重复装载模型）。

用之前先满足两件事：**用第 1 节的「加载牙科 CBCT」载入一例牙科数据**（模型是在牙科 CBCT 上训练的，neck_ct 头颈序列的分割结果没有意义；本页首行也固定写着这条前置），以及三维画面在可见区（推理本身不需要画面，但后面抓证据图需要）。

按钮**按使用顺序排成两行**，读数（状态行）排在操作之后：装载模型 → 牙齿自动分割 → 逐牙自动测量 ｜ 种植位点推荐 → 导出取证数据 → 清除 AI 结果；第三行是「显示 AI 掩膜」开关与「换一例牙科 CBCT」。

| 控件 | 做什么 | 什么时候用 |
|---|---|---|
| 状态行 | 显示运行时版本、**dlopen 命中的 so 路径**、阈值、实例数/牙齿体素、**耗时分解（预处理+推理+后处理=总计 ms）**、新增 Native 内存、掩膜网格与体素大小 | 报告里 PC-05 的延迟/内存数字与这里**同源**，不用另外算。它放在按钮下面，跑一次多长读数只往下推说明文字，不会把按钮顶走 |
| **装载模型** | 加载 ONNX Runtime 与 `teeth_cnn.onnx`，读随包规格里的标定阈值 **0.49** | 每次进入页面后先点一次。失败只会禁用 AI 按钮，**一期的测量/ROI/规划/报告照常可用** |
| **牙齿自动分割** | 整块体数据一次推理 → 阈值掩膜 → 连通域分牙（<8 体素的碎块丢弃）→ 每颗牙算质心/长轴/包围盒/平均 HU/体积 | 约 1 秒（真机实测 `预处理 659 + 推理 331 + 后处理 7 = 997 ms`）。跑完状态行出现「分割 N 颗 · 牙齿体素 M」 |
| **逐牙自动测量** | 每颗牙建一条 **「AI 掩膜」ROI（R-06）**，并挂 **体积（M-04）+ 骨密度（M-08）** 进结果列表 | 想快速拿到全口每颗牙的体积/密度时。重跑**不会**堆双份：同一颗牙的 ROI 原位复用，旧的自动行先清后写 |
| **种植位点推荐** | 在分割结果里找缺牙间隙，按骨高/骨宽/间隙下 HU 打分给候选（默认净间隙 ≥5mm、最多 12 条） | 弹窗按分数降序列出，标题带摘要（`AI-03: 8 个候选位，最高分 90（上颌）`）；**点一条即落一颗按建议姿态与规格的种植体**，随后走第 5 节同一套安全判级（红/黄/绿、骨高/骨宽/神经距/间距） |
| **显示 AI 掩膜** | 只影响绘制，不影响数据 | 掩膜轮廓按**当前切面与层位**画，切层时轮廓跟着变；实例很多时只画最大的若干颗（防止叠加层掉帧） |
| **换一例牙科 CBCT** | 等同第 1 节的「加载牙科 CBCT」，不用切回 tab 4 顶部 | 想对比另一例时。**换例之后必须重新点「装载模型」**：ORT 会话挂在 `MeasureSession` 上，会话重建后模型要重装载 |
| **导出取证数据** | 把真机算出的特征张量、概率图、掩膜、实例编号图写成一个 `.bin` 落到应用私有目录 | 开发/验收用：状态行会给出字节数与 `adb shell run-as … cat …` 拉取命令，主机脚本可与参考夹具逐元素比对。普通使用不需要点 |
| **清除 AI 结果** | 丢弃本次推理结果（掩膜叠加与 R-06 统计随之为空） | **不会删掉**已经生成的「AI 掩膜」ROI 和测量行，**也不会释放 ORT 会话**（再点「牙齿自动分割」无需重新装载）。要重跑就直接再点分割 |

结果列表里 AI 生成的行长这样：`#28 AI 掩膜 AI 牙 U6(#10) 掩膜`（ROI 行）、`AI 牙 U6(#10) 体积`（M-04）、`AI 牙 U6(#10) 骨密度`（M-08）。名字里的 `(#10)` 是分割实例编号，`U/L/R` 是牙弓与象限归属；点 ROI 行会在摘要区跑一次量化并显示体积/HU/权重体素/耗时，与手工 ROI 完全同一套读数。条目多了之后「6) 结果 Results」会自动收起，核对 AI 行时记得点开。

本页底部**固定展示**这段禁忌文案（不是可选说明）：`⚠ 粗筛不是结论：AI-01 实测 F1 0.58（PRD 门槛 0.85）…`，内容即下面这组限制。

⚠️ **必须知道的精度限制**（这条决定了 AI 结果能不能用）：

* 本模型在**没见过的测试例**上 F1 = **0.58**，**没有达到 PRD 要求的 0.85**。链路、耗时、取证都是真的，**精度不够**。
* 常见后果是**相邻几颗牙被连成一整块**：真机出现过 8.51 cm³、4.93 cm³ 的"单颗牙"（一颗磨牙量级只有 0.4~1.0 cm³）。**体积明显偏大的那几条请当作"一组牙"看，不要当单颗牙用于方案设计**。
* 同理，「种植位点推荐」里的间隙宽度是**相邻实例之间**的距离：实例被合并时间隙会虚高（真机出现过 `间隙 88.1mm`、`48.8mm` 这种解剖上不可能的值）。**这类候选直接丢弃**；打分与红黄绿判级本身仍按第 5 节的标准执行，可信。
* 掩膜轮廓是 2D 叠加、不做深度剔除，密集区会前后叠在一起。
* **AI 不替代人工勾画**：需要精确单牙数据时，仍用第 3/4 节的工具手工测量或建 ROI；AI 的价值是先把全口粗筛出来，再由你逐条核对。
* 自动分割只覆盖**牙齿**。颌骨、下牙槽神经管、气道的自动分割（PRD AI-02）**没有提供**，神经管仍要用第 5 节手工描记；报告文字自动生成（AI-04）也没有提供。

## 8. 归档与报告（「7) 归档与报告 Archive & Report」）

这一节是**共享区**：不论当前停在 tab 4 还是 tab 5，它都留在面板底部，导出时把测量与 AI 条目一起写进同一份报告。

| 按钮 | 结果 |
|---|---|
| 保存归档 | 写 `measurements/`、`annotations/`、`plans/` 三份 JSON（按 StudyUID+SeriesUID 命名），同时留 `.bak` 备份；日志 `saveAll ok=3/3` |
| 恢复归档 | 读回同一一份数据并重建列表、叠加层与安全评估；退出页面或杀掉应用后重新进入，用这个按钮继续上次的工作 |
| 导出 PDF + SR | 先弹「报告署名」输入操作者名，点「导出」后依次执行：存三份归档 → 抓当前画面做证据图 → 生成 PDF → 生成 DICOM SR → 读回 SR 自校验；完成后摘要区逐行显示四项结果。**导出前务必把三维画面滚回可见区**，见下方注意事项 |

产物位置（应用专属目录，无需 root）：

```
Android/data/com.example.dcmtkdemo/files/reports/{StudyUID}_{时间戳}.pdf     ← 报告
Android/data/com.example.dcmtkdemo/files/sr/{StudyUID}_{时间戳}.dcm          ← DICOM SR（可 C-STORE 上传 PACS）
files/screenshots/{StudyUID}_{时间戳}.png                                     ← 证据截图
files/{measurements,annotations,plans}/{StudyUID}_{SeriesUID}_*.json         ← 归档
```

报告固定六章：一、患者与数据；二、测量结果（M-01~M-08）；三、兴趣区（R-01~R-06，含 AI 掩膜）；四、种植体规划与安全评估（S-01~S-06）；五、人工标注（A-01~A-07）；六、图像证据。内容多时自动分页（A4），条目与画面证据同源，不会「报告里一个数、屏幕上一个数」。AI 生成的条目会带来源标记（备注 `AI-01 自动分割`），与手工条目在同一张表里，便于逐条核对。

> **AI 结果与归档的关系**：三份 JSON 存的是 ROI 定义（含实例编号）与测量值，**不存掩膜体素场**（那会让归档从几 KB 涨到几十 MB）。所以「恢复归档」后 AI 行会先显示「待重算」，再点一次「牙齿自动分割 → 逐牙自动测量」即可全部回填，**同一批 ROI 原位复用，不会新增重复条目**。

> 导出耗时主要在抓帧（GPU 读回）：真机实测整条链路 `exportAll cost=1381~1712 ms`，期间页面会显示「正在导出报告...」，完成后按钮恢复可用。中途不要退出页面。

> ⚠️ **导出前请把三维画面滚回可见区**。画面被滚出屏幕时渲染线程不再出帧，证据图会抓成**全黑**，而日志仍然打 `evidence=true`（肉眼要在报告的「六、图像证据」里才发现）。真机已复现：画面可见时 PNG 282,849 B / 有效像素 7.13%，画面滚出屏后 PNG 只有 7,760 B / 有效像素 0%。该场景的自动保护（全黑判空并提示）尚未实现，见 `doc/TEST_REPORT.md` §4.4。

## 9. 提示语对照（`3) 三维画面` 下方那一行文字是什么意思）

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `已取 n/2 点`、`已取 n/3 点` | 采点中 | 继续点击 |
| `当前切面未拾取到点` | MPR 下点在切面影像之外 | 往切面图像内部点，或先调窗让目标结构可见 |
| `闭合无效：还需 N 个点（当前 M 点）` | 按了「闭合路径」但面积多边形不到 3 个点 | 继续在当前切面点够 3 个点再按；草稿**保持原样**没有丢 |
| `闭合无效：先在切面上点出至少 3 个点` | 当前没有面积草稿（一个点都没取，或工具不是面积） | 切到面积工具、在当前切面点出至少 3 个点 |
| `体积测量需要拖出一个有效区域` | 只点未拖，或按下与抬起都落在空处 | 按住有骨面的位置再拖动 |
| `区域太小（每边需 >= 1.0mm），已取消` | 盒退化 | 拖大一些 |
| `未拾取到点：请对准骨面或切面再点击` | 按下点没有命中表面 | 旋转视角后再按下，或调整窗宽窗位 |
| `未拾取到骨面：请对准牙槽嵴点击` | 种植体入口点落在骨面之外 | 对着牙槽嵴顶再点 |
| `缺少子 ROI` | 组合 ROI 的 A/B/C 有一个已被删除 | 重新选择存在的子 ROI |
| `待重算` | 输入点不足、体数据变更，或该条是 **AI 掩膜 ROI 而当前没有推理结果**（恢复归档后必然如此） | 手工条目：重新取点或恢复对应 ROI；AI 条目：重跑一次「牙齿自动分割」+「逐牙自动测量」 |
| `未找到数据字典 dicom.dic，请先在 CBCT Parse 页解析一次序列` | SR 生成需要 DCMTK 字典 | 先去 CBCT Parse 页解析一次再导出 |
| `AI 未装载（模型未加载）` + 一行 so 候选路径 | 还没点「装载模型」，或 `libonnxruntime.so` 没被 dlopen 到，**或刚换/重解析了病例**（会话重建后旧的推理引擎已随之析构，状态会被清零重新置灰） | 点「装载模型」；若状态行的「dlopen 命中」为空，看日志 `CbctMeasureAi` 的候选链，确认装的是 arm64-v8a 包 |
| `AI 不可用：…` / 通道不匹配提示 | 模型释放失败、会话未建（没解析序列）、或模型输入通道数与特征构造不一致 | 先解析序列再装载；换模型时确认它仍是 6 通道输入 |
| `没有可建的测量（先做分割）` | 「逐牙自动测量」在推理结果为空时点了 | 先跑「牙齿自动分割」 |
| `AI-03 需要先有分割结果（牙弓与咬合平面来自它）` | 推荐依赖掩膜，没有掩膜就没有间隙 | 先跑分割 |
| `没有可用的缺牙间隙（牙数不足或间隙过小）` | 检出的净间隙都小于 5mm，或识别到的牙太少 | 属正常结果；也可先手工测量（第 5 节） |

## 10. 使用建议与已知限制

* **先 ROI 后测量**：需要骨密度/体积统计时，先建阈值或盒 ROI，再在 ROI 行上取量化，比手工点采样更稳。
* **神经管一定要描记完整**：S-05 的红色警告依赖神经管路径；未描记时相关字段显示未测量而不是 0。AI 也**不会**自动分割神经管（AI-02 未交付）。
* **切层再描记**：面积/截面标注/神经管都绑定当前 MPR 层，跨层描记请逐层切换，不要靠旋转画面「脑补」深度。
* **双指缩放与描记互斥**：测量态下单指被工具接管，需要调整视角时用双指；本页面没有「长按旋转」之类的隐藏手势。
* **截图证据是二维叠加**：证据图与屏幕所见一致，但不含深度遮挡剔除，密集区域可能出现前后图元叠在一起的情况。
* **AI 是"粗筛"不是"结论"**：分割精度未达 PRD 门槛（F1 0.58 < 0.85），且存在把相邻牙连成一块的倾向；用它节省的是"逐颗牙手工点"的时间，省不掉"逐条核对"。详见第 7 节的限制清单与 `doc/AI_ONNX_TEST_REPORT.md`。
* **推理需要整块体数据，与画面无关**：可以在 MPR 任意层位、任意窗宽窗位下跑，结果不变；但结果列表里的 AI 行要点一下才量化（大掩膜会比较慢：真机最大的一条实测 178 ms，其余每颗牙 0~1 ms）。
* **AI 只在 arm64-v8a 设备上可用**：APK 只打包了该 ABI（为了压住"模型+运行时 ≤80MB"的预算），其它 ABI 设备装载会失败并禁用 AI 按钮。
* **页面是竖排面板，三维画面固定 300dp**：`1)~7)` 从上到下串在一列里，三维画面高度刻意压到 300dp，因为它自己会吃掉竖着拖的手势（当成旋转），面板高度不够时你就滚不过它。取点前确认三维条占屏的比例正常；如果滚到底只剩一条窄带，点中的会落在渲染体外，表现为一直报「未拾取到点」。
* **tab 4 / tab 5 切换不影响数据**：只切显隐，会话、草稿、AI 结果都保留；不用重新装载模型，也不会丢掉正在描记的多边形。
* **叠加层文字标签只做了同帧避让，密集场景仍会压字**：标签互相压住时下方那条会整行下移（最多试 6 次），但种植体/AI 推荐位点密集排布时仍可能出现两个标签挤在同一行的情况；需要看清某一条时点它的结果行，或先用双指放大。
