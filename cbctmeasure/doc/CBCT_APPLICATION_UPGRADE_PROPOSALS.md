用途：给你逐条勾选「采纳 / 缓议 / 否决」。每条都写清了**外部依据**、**本项目现有落点**（具体到文件/类）、
**MVP 与完整版的差别**、**改动风险**（是否碰 `:cbctdeal` / `:rawpixeldeal` / NDK）、**可落地的验收口径**。

先说三条硬约束（不建议突破）：

1. **PRD 把 STL 导入/配准/导板输出列为 Out of Scope（Phase 3）**（`cbctmeasure_prd_gen.py:405`）。

2. **`:rawpixeldeal` 有强制回滚基线**（显示效果不比 `e790f7d` 好就回滚）；本清单里只有 P-04（HU 换算展示）

3. **AI 侧一切结论仍是"粗筛"**：`AI-01` 实测 F1 0.5828 < PRD 0.85，根因是**只有 2 例可用数据**
   （`cbctmeasure/src/main/assets/dental_cbct/`）。所以 P-01/P-02/P-12 的本质是"把数据与权重的缺口补上"，

## 1. 第 1 批：低风险、无新依赖、可直接真机取证

### P-03 逐条「实例可信度」标记（把现在的"全局一句禁忌"做成"每条一个判据"）

- **外部依据**：牙网格分割领域已把**不确定性估计**当可靠性前置条件
  （[正畸三维牙网格分割的不确定性估计与蒸馏评估](https://www.ebiotrade.com/newsf/2026-10/20261009034750143.htm)）。
- **本项目落点**：`AiCore.cpp` 的实例统计已有 `voxels / bboxMin/Max / meanHu`；
  `MeasurementManager::aiAutoMeasure`（`:658`）与 `AiPlanner::recommend`（`:113-134`）是消费方；
  UI 侧 `fragment_cbct_ai.xml` 的 `tv_ai_caveat` 目前只有一句全局提示。
- **要做什么（MVP）**：新增一个纯函数判据 `toothCountPlausible(voxels, bbox)`：
  用「单牙典型红网格体素区间」+「包围盒长轴是否 > 牙冠宽度阈值」推出
  `该实例估计含 N 颗牙`，落到 3 处：结果行标题后缀、`MeasureOverlayView` 标签、PDF/SR 的 note 字段。
  超合并实例的 M-04/M-08 数值直接标"按牙组读，不作单牙结论"（现在这句话要用户自己去读全局提示）。
- **为什么值得先做**：它**不动模型、不动像素算法**，却把第 7 轮 D-12 的"数值口径正确但临床不可信"
  变成界面可自证；且它是 P-01/P-02 上线后的**默认防呆层**。
- **验收**：真机上 0101 实例 #1（4,927 红体素 / 覆盖 39,216）必须被标为"多牙合并（估计 ≥5 颗）"，
  #6~#24 小实例标为"接近单牙"；主机单测给边界表；截图 + `aiResultToJson` 字段双证。
- **工作量**：2~3 人日。**风险**：低（core 纯函数 + UI 文案）。**决策点**：单牙体素区间的定标值
  用文献值还是用本项目 GT 自算（我建议自算：`src/host/ai/gt/` 里有专家 GT）。

### P-04 HU/灰度定量的可信度治理

- **外部依据**：CBCT 灰度值≠诊断级 HU，跨机种/跨 FOV 不可比是公开共识
  （[锥形束 CT 测量骨密度的研究进展](https://wap.cnki.net/qikan-YXZS201805033.html)、
  [多机种 MPR 牙槽骨评估的信度与一致性](https://www.ebiotrade.com/newsf/2026-7/20260722002311050.htm)）。
- **本项目现状**：M-08「骨密度」是**裸 HU 统计**（`RoiExtractor::analyze` 的 `meanHu/sdHu/minHu/maxHu`），
  只有 DICOM `RescaleSlope/Intercept` 的线性换算路径（`CbctParseFragment.kt:416`），无体模校准。
  AI 推荐打分（`AiPlanner`）里也用了这个数值，等于把"不可比"的量喂给了排序。
- **要做什么**：① 在 ROI 量化行与 PDF「骨密度」章节展示**换算来源**（slope/intercept 原值 + 是否单位 HU）；
  ② 加一个**相对刻度锚点**：让用户在颏联合/结节区手工画一个"参考 ROI"，其余骨密度一律报
  `Δ相对参考区` —— 无体模也能让同一病例的多时间点对比有意义（这是本项目现在唯一做不到的定量场景）；
  ③ 报告模板把"该数值为 CBCT 灰度，不能跨机种比较"写成固定条款（对齐现有禁忌纪律）。
- **边界**：**绝不改 `:rawpixeldeal` 的调窗/算子**；换算只在展示层与 `VolumeRef` 读取处标注，
  像素路径零改动，避免触发回滚基线。
- **验收**：真机对同一 ROI 连续 3 次量化，均值差 < 0.1 HU；参考锚点变更后所有相对值同步刷新且重算日志齐。
- **工作量**：3~5 人日。**风险**：低。**决策点**：要不要把 AI-03 的打分改成用"相对参考区"值
  （我建议改，但这是评分口径变化，需要你确认）。

### P-08 面向用户的导出包（ZIP → SAF）

- **依据/动机**：竞品都能"一键生成测量报告"，而本项目的 JSON 归档只落在应用私有目录
  （`store/MeasurementStore.kt:43-45`，需 `adb run-as` 才能取），普通评审者拿不到机器可读数据 ——
  我们的差异化（可复核）在演示时是**隐性**的。
- **要做什么**：`btn_export_report` 旁加「导出数据包」，把 3 份 JSON + `.bak` + PDF + SR + 证据 PNG
  打 ZIP，经 `ACTION_CREATE_DOCUMENT` 写到用户可见位置；再加一份 **CSV**（每行一条测量记录，
  列：id/type/name/value/unit/roiId/elapsedMs/可信度标记）。CSV 是给 Excel/统计的最快入口，成本几乎为零。
- **验收**：真机导出后用主机 `unzip -l` + `pandas.read_csv` 直接读通，字段与 `*_measure.json` 逐条对齐。
- **工作量**：1~2 人日。**风险**：低（纯 Kotlin，复用现成 `ReportJni.exportAll` 的产物路径）。

### P-11 工程治理（性能、真取证、回归脚本化）

- **三项**：
  1. **D-12**：`RoiExtractor` 对 AI 掩膜 ROI 的候选集做「按实例包围盒分块 + 只扫非零体素」，
     把 1,121,796 遍历降到 ~39,216 量级；组合 ROI 改为复用子 ROI 已算出的体素集合。
     目标是掩膜类 ROI 单条 ≤50 ms（PC-01），组合 ≤120 ms。**不改数值口径**（用同一份 parity dump 证明 R-06 体积逐位不变）。
  2. **PC-02 真取证通道**：加一个调试开关用 `Choreographer`/帧计数器统计**真实** vsync 帧率，
     并写一条高密度手势注入脚本（`input motionevent` 批量）替代 `input swipe`，否则 30 FPS 永远无法定论。
  3. **回归脚本化**：本轮临时写的 `/tmp/dcmtk_verify/round7/{vptap,scrollto}.py` 固化进
     `.qoder/skills/android-adb-ui-regression-loop/scripts/`，并在 `references/checklist.md` 补 CBCT Measure 的
     逐项期望日志行（含"动作后立刻重定向 logcat，别先看一眼"这条本轮丢日志的教训）。
- **工作量**：5~8 人日。**风险**：1 动 C++ 但不动显示；2/3 只动调试与工具。
- **为什么放第 1 批**：后面每一批新功能都要靠它做取证；D-12 修掉后 P-01/P-05 的"大体积掩膜"才不会一路超标。

## 2. 第 2 批：把 AI 的能力面从"牙齿"扩到"结构"

### P-01 下颌管/下牙槽神经自动分割（AI-02 的第一子项）

- **外部依据**：下颌管自动分割已是种植规划 AI 综述的标准任务
  （[AI in Planning Dental Implant，MDPI](https://www.mdpi.com/2304-6767/14/5/248)，正文待核）；
  开源的 CBCT 牙齿+牙髓实例分割（**TAPSeg**，牙齿 Dice 91.5~94.2%、牙髓 91.0~92.2%、
  HD95 0.70~1.45 mm，1~2 min/例）与 MICCAI STSR 2025（30 例标注 + 250 例未标注 CBCT，最佳 instance Dice **0.967**，
  代码公开）说明**牙齿/管腔结构分割有可直接复用的公开资产**。
- **本项目价值最高的一点**：它同时解掉三件事 ——
  神经距离 S-05 的输入不再依赖手工描记（描记正是 D-08「撤销无效」的重灾区）、
  AI-03 推荐的间隙候选能真正扣除管腔、`nerve distance` 判级覆盖全段而不是描记点连线。
- **落点**：`AiEngine`/`AiCore` 现在只有 1 个 6→2 通道的 `teeth_cnn`（`MeasureJni` 注册 11 个原生方法）。
  加第二个模型（结构分割）需要：`assets/ai_models/` 新增权重 + `index.json` 声明 +
  `MeasurementManager::boundsMm` 之类的实例查询接口按 mask 来源分命名空间（避免牙齿实例与管腔体素串号）。
  神经管数据结构本身**不用改**：`NervePath.points` + `radiusMm` 已能表达，
  新增"从掩膜中心线提点"的 core 函数即可（纯几何，可主机单测）。
- **MVP 与完整版**：MVP = 主机侧选一个**许可明确**的公开模型（或自训：`src/host/ai/gt/` 已有部分 GT）
  → 输出下颌管掩膜 → 一键转成 `NervePath`（保留手工描记作为修正通道）；
  完整版 = 中心线 + 皮质骨缺损提示（[下颌管皮质骨缺损危险因素](https://www.stomatology.cn/CN/10.13591/j.cnki.kqyx.2026.04.005)）
  → 直接产出 S-05 的"疑似接触/穿突"标注。
- **验收指标**（必须先定，否则又是一次"粗筛上线"）：主机侧 Dice ≥0.85、HD95 ≤1.2 mm（与牙齿任务同量级要求）；
  由管腔掩膜转出的 `NervePath` 与专家手工描记的**神经距离差 ≤1 mm**（这是临床上能被采用的门槛，需要你认可）；
  真机 PC-05 单例推理 ≤5 s、新增模型+运行时仍在 80 MB 内。
- **工作量**：8~12 人日（含数据/权重验证）。**风险**：中（新模型 = 新的确定性/parity 纪律要重建）。
- **决策点**：许可（TAPSeg/STSR 权重的再分发条款）与"是否允许 APK 体积增加 ~20~40 MB"。

### P-02 FDI/牙位编号体系 + 牙·牙髓双通道

- **现状**：牙位命名只有 `AiCore.cpp:526-564` 的 `archAssign`（上/下颌 + 弓内序号），
  测量记录名是 `AI 牙 L2(#1)`；报告里没有 FDI/Universal 概念（Explore 结论：无 FDI/象限体系）。
- **要做什么**：把 `arch + index` 映射成 **FDI 两位数**（象限 1~4 + 位 1~8；无牙位/第三磨牙等异常给"未定位"），
  映射表放 core（纯查表，可主机单测），落库字段 `fdi`，UI/PDF/SR 三处同步；
  SR 侧用 DICOM 的 tooth 标记体系（现有 `SrReport` 走 DCMTK，能加 coded entry 的位置在 measure 项的 code sequence）。
- **顺带**：如果接了 TAPSeg 类模型，牙齿+牙髓是**同一模型的两个输出通道**，
  则 M-08 骨密度可升级为"根管/牙髓腔距离"这类牙体 endo 指标（PRD 未列，属加值项）。
- **验收**：0101 的 24 实例逐条给出 FDI 或"未定位"，与主机 GT 的牙位一致率 ≥ 当前 archAssign 一致率
  （先用现有 GT 做回归基线，不引入新误差源）。
- **工作量**：4~6 人日。**风险**：低~中（命名影响历史归档的可读性，需要 `formatVersion` 升版 + 兼容读旧档）。

### P-05 上气道/气腔体积与最小截面（用现有 ROI 族，不写新算子）

- **外部依据**：CBCT 上气道容积/最小截面用于 OSA 与正畸评估是成熟应用
  （[OSAHS 上气道 CBCT 三维测量](https://read.cnki.net/web/Journal/Article/LCKY201806008.html)、
  [上气道容积与下颌骨相关性研究](https://m.doc88.com/mip-3959168992526.html)、
  [不同矢状骨面型气道形态 CBCT 研究](https://doc.taixueshu.com/journal/20120374kqyxzh.html)）；
  竞品也把它做成标配（`AI+气道测量`，自动/手动双模）。
- **关键判断：本项目现在就能做，因为不需要新算法** ——
  气腔 = `R-01 HU 阈值 ROI`（负 HU 区间，`ROI_HU_THRESHOLD` 已是全体积扫描）；
  体积 = `RoiExtractor` 的 `coverage × voxelMm3`；最小截面 = `R-03 平面裁剪` 逐层扫一遍取面积最小值；
  气道长度 = `M-06 弧线长度` 描记。缺的只是**一个 UI 预设 + 一个逐层扫描的批量入口 + 报告章节**。
- **要做什么（MVP）**：① 阈值 ROI 增加"气腔预设（如 −1000~−150 HU，可改）"；
  ② 「气道逐层截面」按钮：对当前层范围的 `R-03` 批量求面积，输出 `min/mean/体积`，
  内部复用 `ROI_BOX` 的空间包围盒快速路径（**注意 P-11 先做，否则 100+ 层逐层量化会撞 PC-01**）；
  ③ 结果按"最小截面所在层"提供跳转定位。
- **验收**：同一病例 3 次跑逐层扫描，最小截面层与数值一致（确定性）；每层量化耗时 ≤50 ms（P-11 后）。
- **工作量**：4~6 人日。**风险**：低（`:cbctmeasure` 内部，不动渲染）。
- **注意**：这是"体积/截面测量"，不是气道动力学结论 —— 报告免责条款要一起上。

### P-12 公开数据集与权重接入（主机侧，不进 APK）

- **依据**：本项目 F1 0.58 的**根因是 2 例数据**；STSR 2025 提供 30 标注 + 250 未标注 CBCT，
  TAPSeg 提供 CBCT + 48 例 IOS 的分割资产，另有公开的成人牙科 CBCT 数据集（Sci Data，正文待核）。
- **要做什么**：只在 `src/host/ai/` 侧建训练/验证管线与新的 held-out 划分纪律（保持"0101 是测试例"这条不破），
  把 parity 夹具扩展到新增病例；**默认不进 APK**，避免顶爆 PC-05 的 80 MB 预算。
- **验收**：换权重后 0101 的 held-out F1 与 Dice 提升多少，作为 P-01 上线的准入门槛数字。
- **工作量**：6~10 人日（主要是算力和清洗）。**风险**：低（不入包）。

### P-09 植体型号库 + 修复导向（crown-down）偏差指标

- **依据**：种植规划综述的主线正是"修复驱动的位置/角度评估"与"骨量-植体参数匹配"
  （MDPI 综述，正文待核；竞品做"综合评估植区骨量并匹配最优植入参数"）。
- **现状**：`ImplantItem` 只有 `diaMm/lengthMm/pitchDeg/yawDeg/depthMm`，`AiPlanner` 用固定默认值匹配。
- **要做什么**：① 参数化型号库（json 资产，几组常见连接基台/平台切换尺寸）；
  ② 冠方参考：允许用一条标注（`A-*` 标注图元已支持文字/箭头/长度）或一个球面 ROI 表示"预定牙冠中心"，
  算 **植体轴线到冠中心的水平偏差 + 成角偏差**（`MeasureMath` 现成函数）；
  ③ 判级扩展：新增 S-11/S-12 两个指标（偏差阈值需要 PRD 侧给数，不能我拍）。
- **工作量**：5~7 人日。**风险**：低~中（新增判级 = 临床口径，需你/PRD 定阈值）。

### P-10 第三磨牙-下牙槽神经风险分级

- **依据**：AI 预测阻生第三磨牙与 IAN 邻近度已有诊断准确性研究
  （[链接](https://www.ebiotrade.com/newsf/2026-8/20260816195102076.htm)），
  皮质骨缺损是独立危险因素（[链接](https://www.stomatology.cn/CN/10.13591/j.cnki.kqyx.2026.04.005)），
  低/标准/高剂量方案下这些解剖标志的可重复性也被单独研究过
  （[链接](https://www.ebiotrade.com/newsf/2026-9/20260905001118789.htm)）—— 最后这条对本项目有用：
  它说明**同一判据在不同剂量图上不一定稳定**，所以风险分级必须带"来源剂量/FOV"字段。
- **落点**：几何上全部现成（牙根掩膜 vs 神经管路径的 `segmentSegment` 距离 + 接触/穿突判据），
  但需要**新增一个"风险"输出而不是复用 S-05 的安全判级**（S-05 是种植口径）。
- **MVP**：先基于手工描记的神经管 + AI 牙根掩膜给距离与接触标记；自动管腔（P-01）到位后再升级。
- **工作量**：4~6 人日。**风险**：中（又是判级口径，建议排在 P-01 之后）。

### P-07 多时间点叠加对比（superimposition）

- **依据**：竞品用"自动头位校正"实现多期直接叠加比对；STSR 2025 的另一半赛题就是 CBCT↔IOS 配准
  （最佳管线把空间位移压到很低，见 [arXiv](https://arxiv.org/html/2512.02867v1)）。
- **本项目现状**：归档按 `{StudyUID}_{SeriesUID}` 分键可共存，但**没有第二体数据槽、没有配准、没有对比 UI**
  （`FileCompareFragment` 只是元数据/调窗静态对比）。
- **完整版成本高**：`:cbctdeal` 要能同时持两幅体数据（渲染/内存/释放顺序都是硬约束，见 README §边界）。
- **MVP（我建议先只做这个，不动渲染核心）**：
  「同一患者两期」各自跑一次测量 → **差值表**（同名测量按牙位/landmark 匹配，输出 Δ + 趋势箭头）
  + 两期证据图并排。价值：覆治对比/疗效随访立刻可用，且**一行渲染代码都不碰**。
- **工作量**：MVP 4~5 人日；完整版 10~15 人日。**风险**：MVP 低 / 完整版中~高。
- **决策点**：是否扩 PRD 把"配准/多期"从 Out of Scope 移到 Phase 3 需求项。
